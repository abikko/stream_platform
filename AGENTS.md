# Правила работы с проектом

- Общайся с пользователем на русском языке.
- Перед изменениями изучай существующий код и следуй его соглашениям.
- Делай минимальные изменения для текущей задачи; не добавляй абстракций сверх принятой слоистой структуры.
- Не добавляй зависимости без необходимости; предпочитай стандартную библиотеку Go.
- Форматируй Go-код через `gofmt`.
- Перед завершением запускай `go test ./...` и `go vet ./...`; сообщай о препятствиях.
- Добавляй тесты для новой бизнес-логики и исправленных ошибок.
- Обрабатывай ошибки явно, добавляй контекст через `fmt.Errorf("...: %w", err)`.
- Передавай `context.Context` в операции ввода-вывода, поддерживай отмену и таймауты.
- Не записывай пароли, токены и другие секреты в код, логи или Git.
- Не меняй чужие изменения и не выполняй разрушительные Git-команды без запроса.
- README ведёт AI-агент: это краткая шпаргалка по локальному запуску, а не полная документация. Обновляй её при изменении запуска или настройки проекта.
- Проект учебный, но пишем как боевой сервис: сразу разделяем слои handler (HTTP) → service (бизнес-логика) → store (хранилище), зависимости между слоями — через интерфейсы, объявленные на стороне потребителя. Новые сервисы и пакеты всё равно добавляй по мере задач, а не впрок.
